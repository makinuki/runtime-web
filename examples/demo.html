MakiNuki runtime-web demo

Instructions

How to run this page (click to expand) 
1. Build once:  (from runtime-web/)  pnpm build
2. Serve:       pnpm serve          (static server on http://127.0.0.1:5173, no deps)
3. Open http://127.0.0.1:5173/ (serves this page) or /examples/demo.html

Changing mode / proxy / token / registry re-creates the runtime.

Diagnostics: check the browser console for logs; the serve terminal logs each
request (method, status, latency, bytes).

Worker mode (optional): from worker-proxy/ run `pnpm wrangler dev --port 8787 --local false`.
  Browser requests carry the page's own Origin (http://127.0.0.1:5173) - the worker's
  CLIENT_ORIGINS in .dev.vars must include it, e.g.
      CLIENT_ORIGINS = "https://app.example.com,http://127.0.0.1:5173"
  then restart the worker. Token input must match CLIENT_TOKEN in .dev.vars.

Companion mode (optional): open the browser's extension manager, enable
  developer mode, load the unpacked companion-extension/ directory, then open
  the extension popup and click "Connect (grant host access)". After editing
  the extension source, click the reload icon on the extension card, then
  refresh this page. Use the Ping button in the transport panel to verify the
  handshake.

Needs a browser with WASM JSPI support. Browser-side payload validation is a
known follow-up (pnpm e2e --validate exercises validation in Node instead).

Direct mode needs no worker or extension, but browser requests are subject to
upstream CORS. The MangaDex API currently sends no Access-Control-Allow-Origin,
so search/details/pages fail in direct mode from this page; use companion or
worker mode for mangadex in the browser. Direct mode still proves registry,
wasm + sha256, metadata, filters and CORS-open image URLs. The full direct
pipeline is verified in Node (no CORS there): pnpm e2e --search "Yosuga no Sora"
--details --pages --image 0 --latest.
